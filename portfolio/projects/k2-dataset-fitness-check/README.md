# K2 · Dataset Fitness Check

> Point it at any CSV file and get a one-page report of its problems.

![Dataset Fitness Check](../../images/k2-dataset-fitness-check.jpg)
<sub>The fitness report the project's fitness_check.py writes, on its made-up customer export.</sub>

## What I built

It is a Python tool that runs 9 checks on any CSV file, writes a one-page HTML report, and with --fix writes a cleaned copy. On a 5,067-row customer export, 8 of the 9 checks needed a look; on the clean copy only the 100 cities nobody knows were reported. On 48,786 real US home-loan records it missed the government's own codes for "no value", Exempt and 8888, until I added them. The point is to find what is wrong with a file before anyone builds a report on it.

A Python tool checks a file for blanks, duplicates, extra spaces, spelling variants, numbers stored as text, mixed date formats, outliers and column problems, and writes a clear HTML report.

## Interview questions this project answers

<details>
<summary><b>What data did you test it on?</b></summary>

A customer list for Riverstone Supplies, a made-up company: 5,067 rows and 7 columns, generated by Compounza, with no real person or business in it. Problems were added on purpose, such as 40 duplicate rows and 6 revenues typed with two extra zeros. Because I knew exactly what was planted, I could test that the tool finds exactly that, and nothing on the clean file.
</details>

<details>
<summary><b>How does it decide that a column holds dates, and whether they are day first or month first?</b></summary>

I match every value against a list of date patterns, and treat the column as dates if at least 90% of values match one. In the sample the signup\_date column used two formats: 4,462 year-month-day and 605 like 05-03-2025. If any of those starts with a number above 12 while the middle number never goes above 12, the day must come first, so I reported 605 dates as day first. If neither number goes above 12, the tool says it cannot tell and to ask whoever made the file.
</details>

<details>
<summary><b>Why are outliers a "look", not errors?</b></summary>

An outlier is only a value far from the rest of its column, and a very large customer can be real. So the report says to check them rather than delete them. In the sample it flagged 6 revenues, exactly the ones planted by multiplying a real value by 100 to imitate a typing mistake. In a real file only someone who knows the business can say which kind each one is.
</details>
